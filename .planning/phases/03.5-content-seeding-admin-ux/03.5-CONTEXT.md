# Phase 3.5 Context: Content Seeding & Admin UX

**Date**: 2026-07-01
**Phase**: 3.5 — Content Seeding & Admin UX

## Domain

Populate the wiki database with real game content and improve the Payload admin panel for efficient ongoing content management. This is a prerequisite for Phase 4 (Unity Interactive Showcase) so there is actual data to display.

## Decisions

### Content Entry Method
- **Both seed script AND admin panel**: Bulk initial data via a TypeScript seed script (`scripts/seed.ts`, run via `npm run seed`). Admin panel at `/admin` for all ongoing edits after the initial seed.

### Collections to Populate
- **All five main collections**: Characters, Bosses, Minibosses, Relics, Locations.
- Real game assets and lore data are available — no placeholder data needed.
- Media (sprites/images) will be uploaded and linked during seeding.

### Admin UX Improvements
Three improvements locked for this phase:

1. **Slug auto-generation** — When a user types a name in any collection, the `slug` field auto-populates (kebab-case, lowercase). Use Payload's `hooks.beforeChange` or `defaultValue` with `slugify`.

2. **Custom admin thumbnail previews** — List views in Payload admin show the sprite image thumbnail next to each entry name. Uses Payload's `admin.components.Cell` or custom `useListDrawer` approach.

3. **Relation field improvements** — When linking Boss → Location, Boss → Relics etc., the relation picker shows useful info (name + type) not just the ID. Use `admin.description` or labeled `hasMany` relations.

### Content Readiness
- Real game assets ready to import (sprites, names, lore, stats).
- Developer will provide assets; seed script imports them programmatically.

- Payload 3.0 runs embedded in Next.js via route group `app/(payload)/`
- Admin panel at `/admin` — first-run creates initial user
- `image` field on all collections is `type: 'upload', relationTo: 'media'`
- `slug` field currently manual (`type: 'text', unique: true`) — needs auto-generation hook
- Collections currently have no image preview in list views
- Search API already fixed to resolve `image.url` via `depth: 1`
