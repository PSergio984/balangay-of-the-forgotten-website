## 1. Payload 3.0 Seed Scripts (Local API)

### Initialization

In a standalone script (e.g. `scripts/seed.ts`), use `getPayload` — not `payload` from Next.js context:

```typescript
import { getPayload } from 'payload'
import config from '@payload-config'

const payload = await getPayload({ config })
```

- Supports HMR in dev, disabled automatically in production.
- `@payload-config` resolves to `payload.config.ts` in the project root.

### `payload.create()` API

```typescript
const doc = await payload.create({
  collection: 'bosses',   // required — collection slug
  data: {                 // required — document fields
    name: 'Diwata ng Dagat',
    slug: 'diwata-ng-dagat',
    // ...
  },
  overrideAccess: true,   // bypass access control — required for seed scripts
})
```

### Programmatic Media Upload

Upload a file from local disk using `filePath`:

```typescript
import path from 'path'

const mediaDoc = await payload.create({
  collection: 'media',
  data: {
    alt: 'Diwata sprite',
  },
  filePath: path.resolve('./scripts/assets/diwata-sprite.png'),
})

// Then link the media ID to the document:
await payload.create({
  collection: 'bosses',
  data: {
    name: 'Diwata ng Dagat',
    image: mediaDoc.id,   // relation to media collection
  },
  overrideAccess: true,
})
```

**Gotcha**: The `media` collection must have `upload: true` in its config (already the case in this project).

### Seed Script Pattern

```typescript
// scripts/seed.ts
import { getPayload } from 'payload'
import config from '@payload-config'
import path from 'path'

async function seed() {
  const payload = await getPayload({ config })

  // 1. Upload media
  // 2. Create locations (no dependencies)
  // 3. Create bosses (depends on locations)
  // 4. Create characters (depends on locations)
  // 5. Create relics (depends on bosses, locations)
  // 6. Create minibosses (depends on bosses, locations)

  await payload.destroy()
  process.exit(0)
}

seed().catch(console.error)
```

**package.json script**:
```json
{
  "scripts": {
    "seed": "tsx scripts/seed.ts"
  }
}
```

Requires `tsx` or `ts-node` for TypeScript execution.

## 2. Slug Auto-generation

### Option A: Built-in `slugField()` (Recommended — Payload 3.0 native)

Payload 3.0 exports a `slugField()` helper. This is the cleanest approach:

```typescript
import { slugField } from 'payload'
import type { CollectionConfig } from 'payload'

export const Bosses: CollectionConfig = {
  slug: 'bosses',
  fields: [
    { name: 'name', type: 'text', required: true },
    slugField({ useAsSlug: 'name' }),
    // ...rest of fields
  ],
}
```

- Includes lock/unlock UI in admin (user can override auto-slug)
- Auto-generates from `name` on create

### Option B: Custom `beforeChange` Field Hook (Robust fallback)

If `slugField()` has issues in this project's Payload version:

```typescript
import type { Field, FieldHook } from 'payload'

const formatSlug = (val: string): string =>
  val.replace(/ /g, '-').replace(/[^\w-/]+/g, '').toLowerCase()

const formatSlugHook = (fallbackField: string): FieldHook =>
  ({ value, originalDoc, data, operation }) => {
    if (typeof value === 'string' && value.trim() !== '') return formatSlug(value)
    if (operation === 'create' || !value) {
      const fallback = data?.[fallbackField] || originalDoc?.[fallbackField]
      if (fallback && typeof fallback === 'string') return formatSlug(fallback)
    }
    return value
  }

export const SlugField: Field = {
  name: 'slug',
  type: 'text',
  index: true,
  unique: true,
  admin: { position: 'sidebar' },
  hooks: { beforeChange: [formatSlugHook('name')] },
}
```

**Decision**: Use Option A (`slugField()`) first; fall back to Option B if Payload version doesn't export it.

## 3. Admin Thumbnail Previews in List Views

### Mechanism: Custom `Cell` Component via `ui` field

Add a virtual `ui` field (not saved to DB) with a custom `Cell` component path:

```typescript
// In any collection (e.g. Bosses.ts):
{
  name: 'imagePreview',
  type: 'ui',
  admin: {
    components: {
      Cell: '/components/admin/ImageThumbnailCell',
    },
  },
}
```

### Cell Component Implementation

```tsx
// components/admin/ImageThumbnailCell.tsx
'use client'
import React from 'react'
import type { DefaultCellComponentProps } from 'payload'

export const ImageThumbnailCell: React.FC<DefaultCellComponentProps> = ({ rowData }) => {
  const image = rowData?.image as any
  const url = typeof image === 'object' ? image?.url : null

  if (!url) return <span style={{ color: '#999', fontSize: '11px' }}>—</span>

  return (
    <img
      src={url}
      alt={rowData?.name || 'preview'}
      style={{ width: 36, height: 36, objectFit: 'contain', imageRendering: 'pixelated' }}
    />
  )
}

export default ImageThumbnailCell
```

**Critical gotcha**: Component paths must be registered in Payload's `importMap`. In this project, `payload.config.ts` has `admin.importMap.baseDir: dirname`. After adding custom components, run `npx payload generate:importmap` or restart dev server to auto-register.

## 4. Relation Field Label Improvements

### `useAsTitle` (Already in use)

Each collection already has `admin.useAsTitle: 'name'` — this controls the label shown in relation pickers. **Already correct.**

### Appearance Options

Relation pickers can be configured:

```typescript
{
  name: 'sourceBoss',
  type: 'relationship',
  relationTo: 'bosses',
  admin: {
    appearance: 'select',   // 'select' (dropdown) or 'drawer' (slide-out)
    allowCreate: true,      // show "Add New" inline
    allowEdit: true,        // show edit icon on selected
  },
}
```

**For showing name + type**: The picker already shows `useAsTitle` value. To show additional info (e.g. type), either:
1. Add a virtual `label` field via a `afterRead` hook that combines `name + type`
2. Or set `useAsTitle` to a virtual computed field

**Practical approach**: For Bosses/Characters with a `type` field, add an `afterRead` hook that writes a `adminLabel` field combining both — then set `useAsTitle: 'adminLabel'`.
