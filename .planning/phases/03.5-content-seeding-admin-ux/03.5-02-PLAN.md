# Plan 03.5-02: Content Seed Script

## Goal
Create a `scripts/seed.ts` TypeScript script that uses the Payload Local API to populate all five wiki collections (Locations, Characters, Bosses, Minibosses, Relics) with real game data, including uploading sprite images from local disk.

> **Note: `autonomous: false`** — The seed data (names, lore, stats, asset file paths) must come from the developer. This plan creates the seed script structure and wiring; the developer fills in the actual game data arrays.

## must_haves
- `npm run seed` command exists in `package.json`
- Script initializes Payload Local API via `getPayload`
- Script uploads images from `scripts/assets/` before creating documents
- Script creates documents in dependency order: Locations → Characters → Bosses → Minibosses → Relics
- Script uses `overrideAccess: true` to bypass auth
- Script exits cleanly after seeding (`payload.destroy()` + `process.exit(0)`)
- Script is idempotent-safe: checks for existing documents before creating (optional, but preferred)

## Wave 2 — Seed Script Implementation

### Task 2.1 — Create seed script scaffold

<read_first>
- payload.config.ts
- collections/Bosses.ts
- collections/Characters.ts
- collections/Minibosses.ts
- collections/Relics.ts
- collections/Locations.ts
- collections/Media.ts
- payload-types.ts (for TypeScript types of each collection)
</read_first>

<action>
Create `scripts/seed.ts` with the following structure:

1. **Imports**:
   - `getPayload` from `'payload'`
   - `config` from `'@payload-config'`
   - `path` from `'path'`
   - `fs` from `'fs'`

2. **Helper function `uploadMedia(payload, assetPath, altText)`**:
   - Checks if file exists at `assetPath` using `fs.existsSync`
   - If exists: calls `payload.create({ collection: 'media', data: { alt: altText }, filePath: assetPath, overrideAccess: true })`
   - Returns `mediaDoc.id` if upload succeeded, or `undefined` if file doesn't exist
   - Logs a warning if file not found (not an error — seed continues)

3. **Data arrays** (developer fills these in — scaffold with 2-3 example entries each):

   ```typescript
   const LOCATIONS = [
     { name: 'Ang Lagusan', slug: 'ang-lagusan', assetFile: 'location-ang-lagusan.png', /* ...other fields */ },
     // ... developer adds more
   ]

   const BOSSES = [
     { name: 'Diwata ng Dagat', slug: 'diwata-ng-dagat', assetFile: 'boss-diwata-ng-dagat.png', locationName: 'Ang Lagusan', /* ... */ },
     // ... developer adds more
   ]

   const CHARACTERS = [ /* ... */ ]
   const MINIBOSSES = [ /* ... */ ]
   const RELICS = [ /* ... */ ]
   ```

4. **Main `seed()` function** with steps in dependency order:
   - **Step 1: Seed Locations** — for each location, call `uploadMedia`, then `payload.create({ collection: 'locations', data: { name, slug, image: mediaId }, overrideAccess: true })`; store `{ name → id }` map
   - **Step 2: Seed Bosses** — for each boss, upload media, resolve `locationId` from location name map, `payload.create`; store `{ name → id }` map
   - **Step 3: Seed Characters** — similar, resolve `locationId`
   - **Step 4: Seed Minibosses** — resolve `bossId`, `locationId`
   - **Step 5: Seed Relics** — resolve `bossId`, `locationId`

5. **Cleanup**:
   ```typescript
   await payload.destroy()
   process.exit(0)
   ```

6. **Error handling**: wrap main in `seed().catch(err => { console.error(err); process.exit(1) })`
</action>

<acceptance_criteria>
- `scripts/seed.ts` exists
- File imports `getPayload` from `'payload'` and `config` from `'@payload-config'`
- File contains `uploadMedia` helper function that uses `payload.create` with `filePath`
- File contains data arrays for LOCATIONS, BOSSES, CHARACTERS, MINIBOSSES, RELICS (with at least 1 example entry each — even placeholder — so the structure is clear for the developer to fill in)
- File seeds in order: Locations → Bosses → Characters → Minibosses → Relics
- `overrideAccess: true` is present on all `payload.create` calls
- `await payload.destroy()` is called before `process.exit(0)`
- TypeScript compiles without errors: `npx tsc --noEmit scripts/seed.ts` passes (or errors only on missing data — not on type errors in the script structure)
</acceptance_criteria>
