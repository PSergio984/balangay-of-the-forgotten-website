# Phase 5 Plan: Global State Management Migration

## Goal
Migrate the project's event-based state communication (CustomEvents) and component-local states to a central Zustand global state store to reduce re-renders, establish clean data flow, and ensure test stability.

## Success Criteria
1. `zustand` is installed and a central state store `useGameStore` is implemented at `lib/store.ts`.
2. Interactive custom DOM window events (`balangay-ready`, `play-game-theme`, `stop-game-theme`) are fully refactored out.
3. Components ([SiteLoader.tsx](file:///c:/Users/admin/OneDrive/Documents/GitHub/balangay-of-the-forgotten-website/components/landing/SiteLoader.tsx), [ParallaxHero.tsx](file:///c:/Users/admin/OneDrive/Documents/GitHub/balangay-of-the-forgotten-website/components/landing/ParallaxHero.tsx), [AmbientPlayer.tsx](file:///c:/Users/admin/OneDrive/Documents/GitHub/balangay-of-the-forgotten-website/components/audio/AmbientPlayer.tsx), [RolesSection.tsx](file:///c:/Users/admin/OneDrive/Documents/GitHub/balangay-of-the-forgotten-website/components/landing/RolesSection.tsx), [WorldMapSection.tsx](file:///c:/Users/admin/OneDrive/Documents/GitHub/balangay-of-the-forgotten-website/components/landing/WorldMapSection.tsx)) utilize the central store with granular selectors.
4. A Vitest unit test suite `tests/state-store.test.ts` is created and passes, verifying all state transitions.
